## 0. Grounded premise verdict (run before trusting any "avoid norm" rule)

Diagnostic `scripts/diag_norm_vs_grade.py` over all 1330 Virchow2 bags
(`results/diag/norm_vs_grade.md`, montages in `results/diag/`):

- **Feature-norm ‖h‖ is grade-uninformative on Virchow2.** Mean ‖h‖ ≈
  36.3–36.5 at *every* grade (Spearman vs grade **−0.005**, p=0.86);
  within-bag spread is ~1% (cv median 0.012). Norm just separates
  tissue-content from background — **high ‖h‖ ≠ dark bone** (visually
  confirmed: a bone-like structure sat among the *low*-norm patches).
- This **falsifies** the `NOVELTY_NOTES.md` §5 legacy prior "patch norms
  monotone across grades" (true on UNI2, flat on Virchow2).
- It **explains a whole cluster of dead-ends** (DE11, DE13, DE15, and open
  hypotheses H1, H2): they built coverage/presence on `σ(‖h‖)` — a signal
  with no grade content.
- **The signal that *does* track grade**: a supervised fibrosis direction
  `v = mean(G2/G3) − mean(G0/G1)`. On held-out patients, **coverage
  (fraction of patches with ⟨h,v⟩ > τ) Spearman +0.844**, mean projection
  +0.882 (vs −0.029 for norm). This is the clinical "overall density of
  fibre-positive patches" reading.

**Operating rules that follow:**
- **Do NOT key any mechanism on ‖h‖ magnitude.** (Kills the whole
  coverage-by-norm family before it is re-coded.)
- The productive axis is **density / coverage along a learned fibrosis
  direction**, read as a *whole-bag count*, not as attention concentration.
- The advisor's "avoid dark bone / grade overall density" maps to the data
  as: measure *how much* of the bag is fibre-positive, not *which* patch is
  most intense.

## 2. Ruled-out mechanisms (compressed — do not re-walk)

From `NOVELTY_NOTES.md` §4 (DE01–DE32) + the §0 norm finding. Re-test under
the new baseline only with an explicit mechanistic reason.

- **Capacity ≫ ~200k** → overfit/collapse: DeepSet (DE01), Set Transformer
  (DE02), bottleneck=256 (DE21, hard-collapsed to all-G0).
- **σ between bag-rep and ŷ** → fragile under SmoothL1, peaks at epoch 1
  then degrades: additive coverage offset (DE11), bounded sigmoid split
  heads (DE12), multiplicative presence×severity (DE13). Use unbounded
  linear; clamp at the end only.
- **‖h‖-based per-patch priors** → norm is grade-uninformative (§0):
  L2-normalise-then-mean (DE10), coverage offset (DE11), coverage-attention
  reweight (DE15). **Includes open hypotheses H1/H2 as written.**
- **Augmenting the gated-attention softmax with any per-patch prior** →
  stuck in the 0.78–0.80 val plateau (cross-cutting DE11–DE15). Must
  *replace* the softmax-mean, not decorate it.
- **Narrowing the pool** (top-K / argmax) → concentrates updates, worse
  overfit (DE16; K=1 worst).
- **Attention+mean concat / prediction-level blends** → attention branch
  adds nothing over mean (DE17); blends are Pareto-better on *test* but
  worse on *val* (DE23) — a test-time deployment trick, not a val win.
- **Regularisers that don't fit this data**: patch dropout (DE03), input
  feature dropout (DE19), bag subsampling (DE18) — neutral or harmful.
- **Frozen single-axis scalar attention** (prototype OR random direction as
  an *attention scorer*) → under-fits learned attention (DE22). NOTE: DE22
  explicitly leaves **multi-axis** and **coverage-readout** untested.
- **Multi-query cross-attention family** (a29 val 0.7997 best): every
  decoration fails — learned attn over queries (DE28), orthogonality
  penalty (DE26), H10 stack on top (DE24), K-sweep (DE25). Only uniform-mean
  fusion (a40) was positive, and it is seed-fragile.
- **Score-based softmax over a direction with √N temperature** → overfits
  the absolute scale; the "rank structure" was a45's only active ingredient,
  but a45 ranks on ‖h‖ which is grade-irrelevant (DE32 + §0).
- **Test-time tricks / ensembling** (MC-dropout, SWA, EMA, k=5 bag ensemble)
  → not aggregation novelty (DE04, DE05).
- **Multi-class CE** → collapses G0 to 0% recall; never revisit (§5).
- **Recurring meta-pattern**: the *ablation* keeps beating the *main*
  (DE26, DE28, DE32). Simpler + lower-variance wins; over-engineered
  mechanisms add gradient noise. Bias the search toward minimal mechanisms.

## 3. Grading-aligned candidate backlog (ranked; grounded in §0)

Each: idea · why grading-aligned · why NOT a dead-end · ablation · risk.

### C1 ⭐ — Coverage along a *learned* fibrosis direction (density readout)
- **Idea.** Learn unit direction `v` (in bottleneck space); per-patch
  `s_i = ⟨h_i, v⟩`; bag readout = **soft coverage** `c = mean_i σ((s_i−τ)/β)`
  (the *fraction* of fibre-positive patches), then unbounded `Linear → clamp`.
- **Grading-aligned.** Directly the clinical "overall density of
  fibre-positive patches"; §0 measured coverage-along-`v` at Spearman +0.84.
- **Not a dead-end.** DE22 used a direction as *attention* (concentrate);
  DE11/DE15/H1 used *norm* as coverage. Coverage-along-a-*learned*-direction
  is neither.
- **Ablation companion.** (a) **mean projection** `mean_i s_i` — linear, no
  σ, no threshold (this is the safe no-σ control and may itself win); vs
  (b) the soft-coverage form. Also test learned `v` vs frozen prototype `v`.
- **Risk.** The per-patch σ can saturate (DE12/13 pathology). Mitigate: σ is
  *pre*-aggregation (not a gate on ŷ), head stays unbounded, and the mean-
  projection ablation sidesteps σ entirely. Kill if val < 0.81 @ seed=2.

### C2 — Multi-axis (ordinal) projection density
- **Idea.** K=3 *ordinal* axes `v_k = mean(G≥k) − mean(G<k)` (or top-K PCA);
  per-axis coverage/mean of `⟨h, v_k⟩`; concat the K density scalars →
  unbounded Linear → clamp.
- **Grading-aligned + ordinal-aware.** Errors are ±1-adjacent (§5); one
  density coordinate per grade boundary matches that ordinal-local structure.
- **Not a dead-end.** DE22's note explicitly flags multi-axis as *untested*.
- **Ablation.** K=1 (single fibrosis axis = C1) vs K=3 ordinal axes.
- **Risk.** Capacity creep if K large — keep K=3; record params.

### C3 — Two-sided coverage blend (open hypothesis H6, rebuilt on direction)
- **Idea.** Use C1's direction-coverage `c` as the gate; two **unbounded**
  heads `h_low`,`h_high`; `ŷ = (1−c)·h_low + c·h_high`. Targets DE11's
  one-sided-offset failure (could only pull down).
- **Risk (high).** DE12/DE13 killed σ-gated blends. Only attempt with
  unbounded heads and `c` as a *soft* (non-saturating) mix; lower priority
  than C1/C2. Ablation: shared single head (≡ DE11) vs two-head blend.

### C4 — Distribution-shape readout of the projection
- **Idea.** Summarise the whole `{s_i = ⟨h_i,v⟩}` distribution as
  `[mean, p50, p90, coverage>τ]` → Linear → clamp. Captures *how much* +
  *how intense* the fibre signal is.
- **Risk.** Adjacent to DE07 (mean+std/quantile concat) — but DE07 was on
  raw/norm features with no clean ablation. Frame as quantiles of a *learned
  fibrosis projection*. Ablation: mean-only vs mean+quantiles. Medium prio.

### C5 — Multi-scale density fusion (unexplored bucket)
- **Idea.** Pool density at multiple receptive scales over the `rc` grid
  (neighbourhood radii) — fibre meshwork is intrinsically multi-scale.
- **Caution.** §5.5 — do NOT condition on the raw scale bucket (leakage:
  `unknown ⇒ {G0,G3}`). Scale-derived features must be computed identically
  for `unknown` bags. Speculative; lowest priority.

**Start with C1 + its mean-projection ablation (one batch).** It is the most
grounded, most grading-aligned, explains the dead-ends, and is genuinely new.

## 4. Run procedure (how to actually run + audit a batch)

1. **Create** `src/models/novelty_attempts/a52_<name>.py` (next free id is
   **a52**; `a01`–`a51` exist) exposing `Model` + `KWARGS`
   (`input_dim=1280, num_classes=1`). Follow `NOVELTY_SEARCH_PLAYBOOK.md` §3.
2. **Sanity** `python scripts/sanity_novelty.py` — param count, output
   shape `[B,1]` clamped to `[0,3]`, gradient flow.
3. **Single ad-hoc run** with the locked baseline config (see
   copilot-instructions §"Same baseline config") and **omit `--leaderboard`**
   so it doesn't pollute `results/leaderboard.csv`.
4. **Batch** `./scripts/loop_runner.sh a52_<main> a53_<ablation>` (or
   `--batch scripts/batches/<tag>.txt`, or `--auto`).
5. **State** `python scripts/novelty_status.py` (current leader, next id,
   dead-ends).
6. **Multi-seed audit (definition of done)** — before calling anything a
   win, run `scripts/sweep_*_seeds.sh` (e.g. `sweep_paired_extra_seeds.sh`)
   over seeds {0,1,2,3,42}. Results for simple/virchow2/novelty land in
   **`results/leaderboard_v2.csv`** (NOT `leaderboard.csv`, which is legacy
   UNI2-era).
7. **Log** one §9 batch entry in `NOVELTY_NOTES.md` (win or no-win); bump
   `next_module_id` and add a `DEn` row if a family is cleanly invalidated.
   (The user manages git — the agent does not commit.)

### Fast path — parallel + agent-team (preferred for throughput)

Running one novelty at a time is slow (~10–13 min/run, I/O-bound on the
per-epoch `.pt` reload). Features (295 MB) fit in RAM cache and the machine
has 10 cores → SCREEN MANY CANDIDATES AT ONCE:

1. **Agent-team design+build** (a Workflow): N agents each design + write +
   sanity-check one module (distinct ids), grading-aligned, not a dead-end.
   Then **independently re-verify each** (params, output `[1]∈[0,3]`, grad
   flow, permutation- + bag-size-invariance, NO data leakage) before running
   — never trust subagent-written code blind.
2. **Parallel screen at seed=2**:
   `bash scripts/run_novelties_parallel.sh <prefix> 2 4 <id1> <id2> …`
   (npar≈4 fits 10 cores; per-run logs to `runs/<prefix>_<id>_s2.out`,
   experiment dirs via `--prefix`, no `--leaderboard`). seed=2 is a SCREEN only.
3. **Triage**: read val/test from each `experiments/.../<prefix>_*` dir vs the
   same-env references (§6). Anything that clears 0.7888 → deep-review its
   code, then multi-seed audit {0,1,3,42} before any claim (honesty guard §7).
   None clears → log + the agent-team spins the next diverse batch.

Gotchas (learned the hard way):
- **zsh does NOT word-split unquoted vars** — `python … $BASE …` passes the
  whole string as one arg (→ "required: --backbone"). Use explicit flags (the
  runner does) or `${=VAR}`.
- Keep `--num_workers 4 --device cpu` for ALL runs so val numbers stay
  comparable (the val cohort is seed/env-sensitive — even `simple` scored
  0.7888 here vs the documented 0.8182). num_workers changes speed, not
  results (the shuffle sampler runs in the main process), but keep it fixed.

found or the search is exhausted. **Continuity:** always keep ≥1 background

The user can interrupt at any time; status is reported every iteration.

**Per-batch decision rule** (after each main+ablation batch completes):
1. Read val/test for both modules; compare to references — official gate
   val 0.8182 / test 0.9476; path-matched baseline a16 val 0.770.
2. **WIN** — a candidate clears BOTH gates at seed=2 (val>0.8182 AND
   test>0.9476) → immediately run the multi-seed audit {0,1,3,42}. If it
